# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

This is a hardware/firmware project for a TinyML current-sensing dev board (picochu, based on
the Seeed XIAO RP2040). It reads AC current via an onboard ADC, and either logs raw samples to
an SD card for dataset collection, or runs an on-device Edge Impulse–exported classifier to
predict which "case" (electrical load state) is currently active, shown via a NeoPixel LED
(red/green/blue = case 0/1/2).

There is no build system, package manager, or test suite in this repo — it is a progression of
Arduino sketches (`.ino`) plus the datasets they produced, meant to be opened and flashed one at
a time via the Arduino IDE.

## Hardware / toolchain setup

- Board: Seeed XIAO RP2040, programmed via Arduino IDE.
- Add board index URL in Arduino IDE preferences:
  `https://github.com/earlephilhower/arduino-pico/releases/download/global/package_rp2040_index.json`
- Install the "Raspberry Pi Pico" board package (by Earle F. Philhower, III).
- Required Arduino libraries: `Adafruit NeoPixel`, `Button2`, `RPi_Pico_TimerInterrupt`.
- Pin map used throughout the sketches: `SD_CS`, `BUTTON_PIN`, `ADC_PIN=26`, `PIXEL_PIN=12`,
  `POWER_PIN=11`. Note `SD_CS`/`BUTTON_PIN` values differ between early labs (28/27) and Lab7s (5/20)
  — check the specific `.ino` before wiring.
- "Build" = open the target `.ino` in Arduino IDE, select board "XIAO RP2040" and the correct COM
  port, then Upload. There is no CLI build/test/lint command in this repo.

### Edge Impulse inferencing quirk

If flashing `Inference/Inferencing/Inferencing.ino` fails with a `__PKHTB` compile error, patch
the vendored SDK at
`文件\Arduino\libraries\Pico_inferencing\src\edge-impulse-sdk\dsp\config.hpp` — after the

`__PKHBT`/`__PKHTB` macro definitions (see `readme.md` for the exact snippet). This file lives
outside this repo (in the local Arduino libraries folder), not in version control here.

## Repository structure and data flow

The sketches form a linear tutorial progression, each building on the last — read them in order
when making changes to understand intent:

1. **`Lab1/`** — button press cycles `state` 0→1→2, sets NeoPixel color. No sampling/storage yet.
2. **`Lab2/`** — adds SD card writes on button press.
3. **`Lab3/`** — SD filenames are derived from `state` (`caseN....csv`).
4. **`Lab4/`** — writes 1000 random-number samples per press instead of real sensor data.
5. **`Lab5/`** — writes real ADC-sampled data instead of random numbers.
6. **`Lab7s/`** — final data-collection firmware: samples `ADC_PIN` at ~1000 Hz via a hardware
   timer interrupt (`RPI_PICO_Timer`), 256 samples per capture (`SAMPLE_COUNT`). Single tap
   triggers a capture; long-press cycles `state` (case 0/1/2). On completion, writes
   `caseN.dataNNNNN.csv` (columns: `timestamp,data`) to the SD card, auto-incrementing the file
   index by scanning existing files on the card at boot (`printDirectory`/`extractTailNumber`).
   This is the firmware actually used to produce the CSVs under `RealDATA/` and `testDATA/`.
7. **`Inference/Inferencing/Inferencing.ino`** — deployment firmware. Uses the same 256-sample
   timer-driven ADC capture as Lab7s, but instead of writing to SD, feeds the sample buffer to an
   Edge Impulse–generated classifier (`run_classifier`, via `<ISIS_inferencing.h>`) and lights the
   NeoPixel according to the highest-scoring class. `raw_feature_get_data()` is the impulse SDK's
   callback into the local `samples[]` buffer — this is the one piece of the file meant to be
   edited when swapping in a newly exported model (per `readme.md`: "只需要修改include的包即可work"
   — only the `#include` needs to change).

### Vendored Edge Impulse library — `Inference/ISIS_inferencing/`

This is the Arduino library exported from the paired Edge Impulse project
(https://studio.edgeimpulse.com/studio/570210, project "ISIS", impulse #1 — input: single `data`
axis, 256 ms / 256-sample window at 1000 Hz, Spectral features → Dense(30) → Dense(20) →
3-class output `case0`/`case1`/`case2`, ~94.7% validation accuracy, quantized int8, built for
target "Raspberry Pi RP2040"). It was downloaded via Deployment → Build → Arduino library and
extracted here in full (`library.properties`, `src/`, `examples/`) so `Inferencing.ino` has a
matching library in-tree; it is not fetched or generated by any script in this repo. Note it
still bundles vendored CMSIS-DSP/TFLite Micro sources (~20 MB, 1300+ files), which is why the
Arduino IDE needs it in its own `libraries/` search path — for the sketch to actually compile,
either copy/symlink `Inference/ISIS_inferencing/` into the Arduino sketchbook's `libraries/`
folder, or use Arduino IDE's Sketch → Include Library → Add .ZIP Library on a fresh export from
the studio page above. If the model is retrained, re-run Build on that Deployment page and replace
this folder's contents — the library name (`ISIS_inferencing`, from the Edge Impulse project
name) must keep matching the `#include` in `Inferencing.ino`.

### Datasets

CSV files use the schema `timestamp,data` (256 rows per file, one ADC reading per row, produced
by Lab7s/Inferencing's 256-sample capture). The `caseN` prefix is the class label (0/1/2 =
different electrical load states); the numeric suffix is a sample index, not a timestamp.

- **`RealDATA/`** — full collected dataset (~800 files: `case0.sample*`, `case1.data*`,
  `case2.sample*`), used as the primary Edge Impulse training set.
- **`testDATA/`** — held-out subset (same 3 cases, ~150 files) for evaluation.
- **`buf/`** — a working copy of the `case1.data*` files plus `buf.py`, a one-off script that bulk
  renames files (replacing `Class` with `case` in filenames) — an artifact of a prior renaming
  pass, not part of the regular workflow. New data collection should target `RealDATA/`/`testDATA/`
  directly, not `buf/`.

### Model training (external)

Model training happens outside this repo, on Edge Impulse's web platform (not in this
codebase): CSVs are uploaded via Edge Impulse's "Data acquisition" page, an impulse
(DSP + learning block) is designed in their UI, then the trained model is exported as an
Arduino library (.zip) and added to the Arduino IDE, at which point `Inference/Inferencing.ino`
is updated to use it. See `readme.md` for the full step-by-step (steps 8–12).
